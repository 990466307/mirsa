# MIRSA 使用流程

先按 [README](../README.md) 准备编译环境。下面的完整查询程序是 [examples/query_dsl.rs](../examples/query_dsl.rs)，运行 `cargo run --locked --features z3 --example query_dsl` 即可。

## 从源文件开始

待分析的文件 [examples/inputs/query_target.rs](../examples/inputs/query_target.rs)：

```rust
pub fn example(data: &[u8], index: usize) -> u8 {
    let s = data;
    let i = index;
    if i < s.len() {
        // mirsa: access
        let value = unsafe { *s.get_unchecked(i) };
        value
    } else {
        0
    }
}
```

查询程序：

```rust
#![feature(rustc_private)]
use mirsa::{Mirsa, SourceBindings, query::Report};

fn main() -> Result<(), mirsa::Error> {
    let source = "examples/inputs/query_target.rs";
    let bindings: SourceBindings = SourceBindings::new()
        .variable("slice", "s") // $slice 对应源码 s: &[u8]
        .variable("index", "i"); // $index 对应源码 i: usize

    let check: Report = Mirsa::from_file(source)
        .query("$index < len($slice) at 'access", &bindings)?;
    println!("性质结果：\n{check}"); // true

    let info: Report = Mirsa::from_file(source)
        .query("facts($slice) at 'access", &bindings)?;
    println!("抽象信息：\n{info}");
    Ok(())
}
```

标注查询下一条语句执行前的状态；赋值、分支、返回也可以标注。标注名须唯一，不用指定函数名；变量按该位置的作用域解析。直接传字符串时改用 `Mirsa::from_source(code)`，源码同样需要标注。

返回类型为 `Result<Report, mirsa::Error>`。主要数据结构如下（省略逐路径诊断）：

```rust
pub struct Report {
    pub output: Output,
}
pub enum Output {
    Check(CheckReport),
    Facts(FactOutput),
}
pub struct CheckReport {
    pub result: bool,              // true：已证明；false：未证明
    pub definite_violation: bool,  // 当前模型内存在必然违反性质的路径
    pub unreachable: bool,         // 查询点不可达
    pub reason: Option<UnknownReason>, // 未证明的原因
    // 另有 verdict、paths，供需要详细诊断的调用方读取。
}
pub struct FactOutput {
    pub abstract_info: Vec<AbstractFact>, // 范围、长度、空性、指向对象等
    pub symbolic_info: Vec<SymbolicFact>, // 结构化表达式、等价关系、条件等
}
```

普通调用只需读取布尔字段：

```rust
if let mirsa::query::Output::Check(check) = check.output {
    println!("已证明：{}", check.result);
}
```

`false` 本身不表示漏洞。`reason` 可能是信息不足、超出支持范围、预算耗尽或未启用求解器等；求解器的候选模型也不等于可执行的反例。`facts` 返回合并后的信息，不能将不同变量的取值范围自行拼成一条真实执行。

## 接入其他 Rust 项目

使用同一 Rust 工具链，在调用方 `Cargo.toml` 添加固定版本的 GitHub 源码依赖：

```toml
[dependencies]
mirsa = { git = "https://github.com/990466307/mirsa.git", tag = "v0.4.0", features = ["z3"] }
```

本地开发也可将依赖改为 `mirsa = { path = "../mirsa", features = ["z3"] }`。

源码有外部依赖时，用 `.rustc_args(...)` 提供 `--extern`、`-L`、`--cfg` 等参数。外部依赖也需要使用同一工具链编译。当前源码入口不直接接受 `Cargo.toml`。

## 从已有 MIR 开始

在工具的 rustc 回调中，已有 `tcx: TyCtxt<'tcx>`、`body: &Body<'tcx>`、匹配出的 `index_place` / `slice_place: Place<'tcx>` 和目标 `location: Location` 时：

```rust
use mirsa::query::Bindings;

let bindings = Bindings::new()
    .value("i", index_place)
    .value("s", slice_place)
    .location("access", location);
let report = Mirsa::from_mir(tcx, body)
    .query("$i < len($s) at 'access", &bindings)?;
```

两种入口使用同一套分析和结果类型。
