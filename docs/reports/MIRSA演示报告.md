# 演示并讲解使用 DeepSeek DSH 调用 MIRSA 工具，进行风险检测的效果

> 历史记录：本文保留当时的路径和结果；旧演示输入已移除，当前测试结构与运行方式见 [tests/README.md](../../tests/README.md)。

## 一、演示目标

验证一条完整的自动化链路：把 MIRSA（面向 Rust 的静态分析工具）通过 MCP 协议接入 DeepSeek DSH，使 DSH 中的 AI 在只拿到一个源码文件（或一段贴进来的代码）的情况下，能够自主完成「定位风险点 → 确定可用变量 → 陈述安全性质 → 取得工具结论」的全过程，并给出可核验的判定结果。

核心诉求有两条：**性质由 AI 自己写**（因为 unsafe 的安全性质建模不完），**判断由求解器给**（不靠肉眼读代码猜）。

## 二、接入方式

MIRSA 以 MCP 服务器形式对外暴露三个工具，DSH 通过 MCP 客户端调用，模型看到的就是普通工具：

| 工具 | 用途 |
|---|---|
| `mirsa_read_lines` | 读取源文件并返回带行号的文本，用于定位风险点 |
| `mirsa_variables` | 列出指定行可见的源码变量名，用于确定查询所需的绑定 |
| `mirsa_query` | 在指定语句执行前查询一条安全性质，返回判定与证据 |

三点设计要点：

- **标注自动插入**：MIRSA 需要在目标语句前加 `// mirsa:` 位置标记，这一步由工具在内存中完成，**源文件不被修改**；
- **两种输入等价**：传文件路径或直接传代码字符串，行为完全一致；
- **结论只留数据**：判定语义写在服务器指令里（只发一次），每次返回只带 `conclusion` / `location` / `resolved_bindings`，避免重复文本随对话历史累积。

## 三、演示内容

演示文件 `examples/inputs/vulnerable_demo.rs`，共 21 行，含三个 `get_unchecked` 调用点，**无 `main` 函数、无任何标注**：

```rust
pub fn definitely_out_of_bounds() -> u8 {
    let table = [10u8, 20, 30];
    let index = 5usize;
    unsafe { *table.get_unchecked(index) }
}

pub fn bounded_by_constant(data: &[u8]) -> Option<u8> {
    if data.len() >= 4 {
        Some(unsafe { *data.get_unchecked(3) })
    } else {
        None
    }
}

pub fn correctly_guarded(data: &[u8], index: usize) -> u8 {
    if index < data.len() {
        unsafe { *data.get_unchecked(index) }
    } else {
        0
    }
}
```

演示过程中 AI 的动作序列：一次 `mirsa_read_lines` 定位到第 4、9、17 行 → 三次 `mirsa_variables` 核实每个调用点的可用变量 → 三次 `mirsa_query` 分别查询该 `get_unchecked` 的前置条件。

## 四、实测结果

| 位置 | 查询的性质 | 判定 | 说明 |
|---|---|---|---|
| 第 4 行 | `$index < len($table)` | **确定违反** | 证据：`$index = [5, 5]`，`Length($table) = [3, 3]` |
| 第 9 行 | `3 < len($data)` | **已证明** | 守卫 `len >= 4` 覆盖常量下标 3 |
| 第 17 行 | `$index < len($data)` | **已证明** | 守卫 `index < len` 与前置条件完全一致 |

三种结论互斥，且都由求解器给出，不是「看着像」的判断。**第 4 行附带的 `evidence` 是具体取值**：下标确定为 5、长度确定为 3，两个单点区间直接解释了越界原因，无需额外推断。

这一对照体现了工具的实际价值：同样一句 `get_unchecked`，一处是必然越界的真问题，一处在有守卫时被证明安全，一处在无守卫时给不出结论——**三态分明，不会把「未证明」混同于「安全」或「有漏洞」**。

## 五、为 agent 可用而做的接口改进

原始入口要求手工在源码里写标注、手工绑定变量名，对 AI 不可用。为此做了以下改进：

1. **消除手写标注**：改为按行号定位，工具自行在正确位置插入标注（含跳过空行/注释的锚点查找），并复用文件里已有的同名标注。
2. **消除变量名猜测**：`mirsa_variables` 通过逐个引用候选名让分析器真正解析，从而区分「该点不可见」与「可见但类型不匹配」，实测能准确判定 `index`、`table` 可见而 `good_index` 不可见。
3. **绑定默认同名**：`$index` 自动对应源码 `index`，名字不一致时才需显式传入。
4. **DSL 文法经实测后写入指令**：运算符、15 个内置函数逐条验证，并记录两个实际坑——字面量不加类型后缀最稳妥（`$i % 2` 可用、`$i % 2u64` 报类型不匹配），`layout_size`/`layout_align` 要求 `Layout` 操作数。
5. **结论语义前置**：`proved` / `definite_violation` / `unreachable` / 6 种 `reason` 的含义写在指令中，返回值只承载数据。
6. **分析边界写入指令**：过程内分析、无符号下溢未建模、修复后无 `unsafe` 时工具不适用，这三条写进服务器指令，避免 AI 得出错误结论。
7. **路径双形式**：WSL 路径与 Windows 路径均可，后者自动转换为 `/mnt/<盘符>/...`。

## 六、已知局限

1. **过程内分析**：MIRSA 只分析标注所在的函数体，不考虑调用方传入的具体参数。因此不能用「加一个具体调用方」来验证函数内的性质。
2. **无符号整数减法下溢未建模**：对形如 `index <= data.len() - 1` 的守卫，工具证明成立，但当长度为 0 时该算术前提不成立。最小复现 `examples/inputs/underflow_demo.rs`：该处既能证明 `$index < len($data)`，也能证明 `len($data) >= 1`，而同一位置的 `Length($data)` 区间为 `[0, u64::MAX]`，两者矛盾，说明下溢未建模。此结论按真实 Rust 语义分析：debug 下 panic，release 下回绕导致越界。
3. **求解器必须启用**：构建 worker 时必须带 `z3` 特性。漏掉该特性会使所有性质静默变为「未证明」且不报任何错误——这一点已在接入文档中标注。
4. **单文件输入**：当前入口接受单个 `.rs` 文件，不直接驱动 `Cargo.toml`；外部依赖需通过 `rustc_args` 传入 `--extern`、`-L` 等参数。
5. **批量回归基线**：仓库自带 43 个真实样例的回归测试，当前 41 个通过、2 个不符预期（其中 1 个为漏报）。该基线可作为后续改动的稳定性指标。

## 七、结论

本次演示验证了目标链路可用：**DSH 中的 AI 在没有任何人工预处理的前提下，对一个含三处 `unsafe` 调用的 Rust 文件完成了风险检测，并对每处给出可核验的三态判定与具体取值证据。**

工程上确定了两点：

- MCP 是合适的接入层，DSH 侧无需任何定制开发；
- 工具的可用性瓶颈不在分析能力，而在**接口是否对 agent 友好**（标注、绑定、结论语义、分析边界四项），这四项改进后，AI 能稳定走完流程并如实汇报。

后续可按优先级推进：补齐下溢建模以消除第 2 条局限；将「一次编译回答多条查询」合并，减少当前证据采集所需的重复编译；以及在真实项目文件上扩充验证。
